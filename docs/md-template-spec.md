# Формат MD-теста

Это формат, в который AI должен конвертировать учебные материалы. Файл
целиком парсится бэкендом (`backend/src/lib/mdParser.ts`) — синтаксис
нужно соблюдать точно.

## Структура файла

```markdown
---
title: Название теста
description: Необязательное краткое описание
pass_percent: 70
language: ru
---

## Q1 [Networking]
Какой порт по умолчанию использует HTTPS?

- [ ] TCP 80
- [x] TCP 443
- [ ] TCP 22
- [ ] TCP 3389

## Q2 [Hardware]
Какое минимальное количество дисков требуется для RAID 5?

- [x] 3
- [ ] 5
- [ ] 2
- [ ] 4
```

## Правила

1. **Front matter** (между `---`/`---`) обязателен и должен содержать:
   - `title` — название теста
   - `pass_percent` — проходной балл в процентах (число 1–100)
   - `description` — необязательно
   - `language` — необязательно, произвольный код языка контента теста
     (`ru`, `uz`, `en` и т.д.), по умолчанию `ru`. Не переводится на сайте —
     это просто метка.
   - `group` — необязательно, произвольный slug. Если несколько тестов
     (обычно — один и тот же экзамен на разных `language`) имеют
     одинаковый `group`, сайт связывает их: студент видит одну карточку
     с переключателем языка вместо нескольких отдельных тестов. Без
     `group` каждый тест независим — это поведение по умолчанию.

2. **Заголовок вопроса** строго в формате:
   `## Q<номер> [Раздел]`
   Раздел — произвольный текст (не захардкожен в системе), например
   `Networking`, `Hardware`, `Mobile Devices`, `Cybersecurity Basics` и т.д.
   Раздел используется потом в дашборде студента/админа для разбивки
   результатов по темам.

3. **Текст вопроса** — обычный текст сразу после заголовка (одна или
   несколько строк, до первого варианта ответа).

4. **Варианты ответа** — список в формате GFM-чекбоксов:
   - `- [ ] текст` — неправильный вариант
   - `- [x] текст` — правильный вариант
   Минимум 2 варианта. Можно отметить `[x]` у нескольких вариантов —
   тогда вопрос станет multiple-choice (нужно выбрать все правильные).

5. Между вопросами — пустая строка. Порядок вопросов в файле = порядок
   показа студенту.

## Что это даёт автоматически

- Подсчёт правильных/неправильных ответов и итогового процента.
- Сравнение итогового процента с `pass_percent` → пройден/не пройден.
- Разбивку результата по разделам (`[Раздел]` в каждом вопросе) для
  дашборда — какие темы студент знает хорошо, какие плохо.
- Поддержку вопросов с одним или несколькими правильными ответами.

## Как это используется в системе

1. Админ вставляет исходный материал в промпт (см.
   `docs/admin-prompt-template.md`), получает готовый MD-файл от AI.
2. Вставляет MD в форму загрузки на сайте → бэкенд парсит его
   (`POST /api/tests/parse-preview`) и показывает предпросмотр с ошибками,
   если формат нарушен.
3. После проверки админ сохраняет тест (`POST /api/tests`) — вопросы,
   разделы и правильные ответы уходят в базу. Правильные ответы студенту
   никогда не отдаются до отправки его попытки.
